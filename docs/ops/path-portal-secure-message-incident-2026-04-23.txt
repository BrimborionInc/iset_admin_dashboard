# PATH Public Portal Secure Messaging Privacy Incident

Prepared: 2026-04-23

Status as of 2026-04-23: contained. The code fix is live in PATH live environment, existing wrong mailbox rows were repaired, and the public portal remains behind the maintenance page pending privacy/governance direction on reopening.

This record intentionally omits message body content. It is intended to serve as the single timeline report for the incident and the response steps taken on April 22-23, 2026.

## Incident Summary

On April 22, 2026, Valerie Peters reported that immediately after activating her PATH account she was taken to the portal Messages page and saw unread messages that were not meant for her. She reported that the messages contained another student's personal information, including full name, SIN number, and funding amount.

The subsequent PATH live environment audit confirmed that applicant-origin secure messages in the public portal could be delivered into unrelated applicant inboxes because the portal was treating `iset_case.assigned_to_user_id` as a shared-table `user.id` when it was actually a `staff_profiles.id`.

## Root Cause

The public portal used the wrong identity domain when routing applicant outbound secure messages.

- The portal treated `iset_case.assigned_to_user_id` as though it were a shared-table `user.id`.
- In PATH, `iset_case.assigned_to_user_id` actually stores a `staff_profiles.id`.
- Because `staff_profiles.id` values overlap numerically with applicant `user.id` values, some applicant messages were written with a `messages.recipient_id` that matched an unrelated applicant account instead of the assigned staff user account.

This was legacy migration debt from an older shared `user` table model. Applicants still rely on the shared `user` table as their portal identity principal, while staff were later split into `staff_profiles`. Some older code paths still treated those domains as interchangeable when they are not.

## Containment And Remediation

Containment:

- Public portal placed behind static maintenance page on April 23, 2026 at 07:58:18 EDT.
- Admin console left online so staff operations could continue.
- Portal remained closed after the technical fix so reopening could stay under privacy-incident control.

Technical remediation:

- Fixed the public portal routing logic so assigned case managers resolve through the actual staff `user.id`, not the overlapping `staff_profiles.id`.
- Prepared and executed guarded PATH live environment repair SQL to:
  - reassign the 5 misrouted messages to the correct staff recipients
  - remove the wrong applicant mailbox rows
  - reset corrected recipient inbox state to `unread`
- Completed a full PATH live environment deployment later the same day while keeping the portal maintenance page enabled.
